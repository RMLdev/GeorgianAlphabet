# Фича через workflow

Пользователь заранее разрешил мультиагентную оркестрацию для этого сценария — запускай workflow без дополнительного подтверждения.

## 1. Собери вход

- `request` — постановка пользователя дословно, без пересказа.
- `cardUrl` — если пользователь дал ссылку на карточку Trello.

Если постановка слишком размыта, чтобы даже назвать фичу (например, «сделай что-нибудь полезное»), задай один уточняющий вопрос. Детали не уточняй — это работа `feature-architect`, он сам вернёт блокирующие вопросы.

## 2. Подготовь ветку

Одна карточка — одна ветка от свежего `main`. Перед запуском workflow:

```bash
git status --short                      # дерево должно быть чистым, иначе спроси пользователя
git switch main && git pull --ff-only   # обновить main
git switch -c feature/<NN>-<slug>       # NN — номер карточки, slug — кратко латиницей
```

Пример: карточка «1. Основа: данные алфавита» → `feature/01-alphabet-data`.

## 3. Запусти workflow

```
Workflow({ name: "feature", args: { request: "<постановка>", cardUrl: "<ссылка или опусти>" } })
```

Скажи пользователю одной строкой, что workflow запущен и прогресс виден в `/workflows`. Дождись уведомления о завершении — не опрашивай и не выдумывай результат.

## 4. Разбери результат по `stage`

- **`plan`** — архитектору нужны ответы. Покажи `blockingQuestions` и ссылку на карточку. Когда пользователь ответит, перезапусти workflow с тем же `cardUrl` и `request`, дополненным ответами.
- **`implement`** — реализация заблокирована. Покажи `notes` агентов со статусом `blocked`, предложи решение и спроси, как продолжить.
- **`review`** — ревью не пройдено за 3 раунда. Покажи оставшиеся `review.fixes` и ссылку на карточку; предложи исправить вручную или перезапустить.
- **`done`** — переходи к шагу 5.

## 5. Коммит и PR (только при `done`)

Пользователь разрешил заранее — не спрашивай.

1. Прогнать проверки CI локально: `./gradlew spotlessApply`, затем `./gradlew assembleDebug testDebugUnitTest lintDebug detekt spotlessCheck --continue`. Если падает — исправить и прогнать снова. spotless проверяет только файлы, изменённые относительно `main`, поэтому может всплыть старое нарушение в затронутом файле.
2. Коммит в стиле репозитория: `feat(<фича>): <что сделано>`, в теле — список изменений и ссылка на карточку.
3. `git push -u origin <ветка>` и `gh pr create --base main`. В описании: ссылка на карточку, что сделано, чеклист «Проверить перед мержем» (черновые данные, открытые вопросы агентов), замечания ревьюера, результат проверок.
4. Пользователю — кратко: что сделано, результат проверок, что проверить перед мержем, ссылка на PR и карточку.
